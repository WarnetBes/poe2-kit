# SPEC: Советчик раскладки навыков (Keybind Advisor)

> Модуль `core.keybinds` + MCP-тул `poe2_keybind_advisor` + вкладка/секция в overlay
> («🧬 Билды» → «▶ Раскладка»). Вход — PoB-код/XML билда; выход — готовая раскладка
> под геймпад (Xbox / PlayStation нотация) и клавиатуру, с обоснованием каждого слота.
> Статус: **реализовано, Stage 1 + web-вкладка** (№222): `core.keybinds` + MCP-тул 61
> `poe2_keybind_advisor` + вкладка «🎮 Раскладка» в web. Оставшиеся «❓» — живая
> сверка дефолтов фляг/dodge клавиатуры и списка 11 кнопок геймпада (F5/F7) владельцем.
> **Закрыто данными датасета (было ❓ в дизайне):** burst-детектор — тег `Cooldown`
> из `skill_gems_v2` (`Tempest Bell` — да, дурацких эвристик не нужно);
> Spirit-блок — тег `HasReservation` (все 7 persistent эталона);
> Spirit-цена — поле `levels[0].spiritReservationFlat` (Herald of Ice → 30);
> тег `Movement`/`Travel` в PoE2-датасете отсутствует — мув остаётся on
> имени-эвристике + пину (unverified). Web: полный датасет приходит лениво
> через `installBrowserDataset` (fetch ~550 КБ gzip).

## 2. Данные-носители в kit (уже есть, ничего качать)

- `core.build.importBuild(xml)` → `skillGroups[]` (`main`, `enabled`, `gems[]`, `source`, `label`) — связки билда.
- `dataset.getSkillGemDetails(name)` → **`skillTypes[]`** («Aura», «Herald», «Attack», «Spell», …), `castTime`, `is_support` (dataset.ts:180–316 — эвристика classification = наш «сырой» тег; точность ниже официальных тегов poe2db).
- `core.spirit` — резервации аур/херальдов: аура НЕ занимает боевой слот → в раскладку не биндим, но показываем блоком «зарезервировано Spirit N (каст раз при входе)».
- `gemdata` (web/ IPC `buildgen:gemdata`) — полные данные гемов.
- RU-имена гемов — `gemsRuEn` (RU клиент = RU-выдача раскладки из коробки).

## 3. Модель ролей навыка (ядро алгоритма)

Каждый активный гем из `skillGroups` классифицируем в одну роль:

| Роль | Признак (по skillTypes + эвристики kit) | Приоритет слота |
|---|---|---|
| `primary` | группа `main` (маркер PoB) или максимум DPS-веса из estimate | лучший слот (R1 / LMB) |
| `secondary` | прочие атакующие/заклинания без кулдауна | face / Q W E |
| `burst` | большие кулдауны/сот-скиллы (❓ детектор по cooldown: в gemdata поля кулдауна нет → честный флаг «burst по эвристике имени/описания», помечать unverified) | средний (T / L2+face) |
| `movement` | travel/dash (❓ PoE2-тег неизвестен без данных: в Monk это Tempest Flurry/Dodge; решает фильтр по skillTypes 'Movement' ЕСЛИ есть, иначе эвристика имени + ручной пин) | высокий доступ (R2 / Space-сосед) |
| `buff` | self-buff с длительностью (❓ по описанию) | низкий (редко жмём) |
| `curse/mark` | skillTypes 'Curse'/'Mark' (❓ сверить теги с poe2db) | по частоте: T / L2+face |
| `aura/herald` | `skillTypes` ∈ {Aura, Herald} (dataset.ts:196 — уже реализовано kit'ом) | НЕ биндим: Spirit-блок |
| `wtf` (не распознано) | — | честный «укажи вручную» + кнопка пина в UI |

Эвристики с галочкой «❓» — не выдумывать поведение: в выдаче помечать `unverified: true` + причина.

## 4. Целевая раскладка (дефолт-профиль, editable)

### 4.1 Геймпад (F1–F3; Xbox → PS нотация автоматом)

Слой 0 (без модификатора) — «_TV» боевые:

| Кнопка (Xbox / PS) | Категория | Обоснование из F3 |
|---|---|---|
| RB / R1 | primary (осн. атака) | GGG сам кладёт primary fire на R1 |
| RT / R2 | movement или primary-2 | второй по доступности триггер |
| LB / L1 | **Dodge Roll** (системный, F2) | рекомендация GGG |
| Y / △ | secondary-1 | face |
| X / □ | secondary-2 | face |
| B / ○ | curse/mark или buff | face |
| A / ✕ | **Interact всегда системный** (не перебивать) | стандарт консолей |
| D-pad ▲▼ | Life/Mana Flask («Any Flask» бинды) | рекомендация GGG (F2) |
| D-pad ◀▶ | фляги 3–5 / charms | там же |

Слой 1 (удержание LT / L2) — редкие:

| Кнопка | Категория |
|---|---|
| L2+RB, L2+RT | burst-скиллы (атачменты у GGG там же) |
| L2+Y/X/B | buff, rarely-used, town-portal |
| L2+D-pad | Overlay Map, Portal Scroll (F2, рекомендация GGG) |

Итого занято навыками: ~7–9 слотов из ~17 доступных — запас под рост билда (wedge: «+8 слотов свободно» в выдаче).

### 4.2 Клавиатура (F5)

| Клавиша | Категория |
|---|---|
| LMB | primary |
| RMB | movement/dash или secondary |
| Space (❓ дефолт) | Dodge Roll |
| Q, W, E, R | secondary-1..4 (по частоте: Q — самое частое) |
| T | burst |
| MMB | buff/utility |
| 1–5 (❓) | фляги |
| Ауры/херальды | Spirit-блок, не биндим (F6) |

RMB для мув-скилла — если WASD-режим; при клик-муве RMB = secondary (профиль `movement_mode: 'wasd' | 'click'`).

Профиль-параметры тула: `platform: 'xbox' | 'playstation' | 'keyboard'`, `modifier_button` (L2 по умолчанию), `hand_size`-заглушка НЕ нужна — без гаданий; `overrides: {gemRole}` для пинов пользователя.

## 5. Выход тула `poe2_keybind_advisor`

Аргументы: `code` (PoB-код/XML, обяз.), `platform`, `movement_mode`, `overrides?`.
Выдача (markdown):

1. **Таблица раскладки** — слот → навык → роль → почему (одной строкой).
2. **Spirit-блок**: ауры/херальды → суммарная резервация, «bindung не нужна, каст при входе/после смерти».
3. **Бюджет слотов**: занято N / доступно M, запас.
4. **«Ручная установка» под платформу**: пошагово БЕЗ выдумки — путь меню из F4 (Inventory → Skills → Set Skill Bind / пауза → Bind Screen), ТЕКСТ-инструкция без ложных клавиш.
5. **unverified-список**: роли с ❓ и что сверить владельцу живьём (сверка = короткий скрин Bind Screen).

## 6. Интеграция

- `packages/core/src/keybinds.ts` — чистая функция `adviseKeybinds(b: BuildImport, opts): KeybindAdvice` (никакого I/O, детерминированная, юнит-тесты на эталоне 28880 + 2–3 класс-разных билда).
- `apps/mcp/src/tools/keybinds.ts` — регистрация тула (61-й, registerTool-паттерн buildGuide.ts).
- Overlay: секция « раскладка» в «🧬 Билды» поверх уже собранного билда (только text-рендер таблицы ~30 строк, БЕЗ новых IPC — рендер из того же build-state) — **вторая фаза, пока НЕ реализовано**.
- Web: **реализовано как полноценная вкладка «🎮 Раскладка»** (решение владельца №222: web — основной UI-вход, а не стат-карточка): вставка кода/decoded XML, платформа+режим, карточки слотов, Spirit-блок; датасет гемов лениво через `installBrowserDataset`.

## 7. Чего НЕ делаем (границы)

- НЕ читаем/пишем конфиг управления игры — GGG не экспортирует бинды файлом (Ⓐ клеймы без пруфа — не делаем); советник = генератор инструкции, а не апликатор.
- НЕ д distinguishым модель геймпада (одна DTO, нотация — рендер-деталь).
- НЕ выдумываем кулдауны/теги: отсутствие данных = `unverified` + пин пользователя.
