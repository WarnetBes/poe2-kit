# SPEC: Hideout Layout Generator / Converter

Статус: дизайн (спека). Реализация — отдельная волна (кандидат №200+).
Дата: 2026-10-04. Основано на: реверс №199 (POH-формат), 12 нативных POE2-экспортах
владельца (`_research/hideout_sites/native/`), разборах POH/HS (`HIDEOUT_SITES_ANALYSIS.md`).

## 1. Подтверждённые факты формата (нативные файлы, 12/12)

- Нативный экспорт игры = POH-формат 1:1. JSON + UTF-8 BOM, схема
  `{version, language, hideout_name, hideout_hash, [music_name, music_hash], doodads}`.
- `doodads` — объект «имя → {hash, x, y, r, fv?}`. **Имя = ключ, дублей нет ни в одном
  из 12 файлов (704 записи, max 103/файл)** 🔎 вывод: одна запись = одно размещение,
  формат не умеет N копий одного декора (или PoE2 их не позволяет — ❓ требует
  проверки в игре: поставить 2 одинаковых, экспортировать).
- Суффикс `(Unique)` — часть имени MTX-варианта из игры (Beacon: «Atziri's Royal Cache
  Stash (Unique)»), не маркер дублей.
- `r` — поворот, uint16 (0..65535 ≈ ×360/65536°). `fv` — вариант оформления:
  наблюдён 0..21, гипотеза «бит 7 = зеркалирование» 🔎 (наблюдён fv 126..142 в №199,
  у нативных 0..14 и 128+ нет, но POH-образцы дают диапазон 128–142 = 128+вариант).
- Хеш декора НЕ выводится из имени (проверено crc32/fnv1a/fnv1/djb2/sdbm × 9 вариаций
  нормализации — 0/234 совпадений, `scripts/hash-experiment.mjs`). Хеши берутся только
  из живых файлов ⇒ **каталог — единственный источник хешей**.
- Координатные системы баз разные (Bloodreaver y до 2477 — многоуровневая; Beacon
  x 302..934 / y 186..1295). Играбельная область ≠ прямоугольник bbox.
- Лимит 750 декоров (текст POH), но формат его не валидирует.
- `music_name/music_hash` — опционально, есть в 5 из 12 файлов (поля с 0.5?).

## 2. Датасет (готов к генератору)

`packages/core/data/game/hideout/decor.json` после слияния:
- 234 имени, 1+ хеш на имя, `seen_in` (POH-образцы + native/*).
- 9 баз POE2 с `observed` (files, maxDoodads, x/y-диапазоны) — затравка канваса.
- Категории: free / store-mtx (эвристика possesive) / unknown — как в №199.

## 3. Уникальность против конкурентов

- POH = каталог + калькулятор «сколько из 750». HS = каталог. **Никто не генерирует
  .hideout.** УТП poe2-kit: офлайн-планировщик → экспорт импортируемого файла.
- gnejs-сайт (sagas) полезен только как паттерн: микротул на одну механику, тёмный
  UI, краудсорс-данные. К хайдоутам отношения не имеет (Boss Sagas/Aldur's Saga).

## 4. Архитектура (все слои уже есть с №199)

### 4.1 core: `hideout.ts` — расширение (новые функции)

```ts
buildHideout(opts: {
  baseHash: number;               // из decor.json.bases
  language?: string;             // default 'English'
  music?: { name: string; hash: number } | null;
  doodads: Array<{ name: string; x: number; y: number; r?: number; fv?: number }>;
}): { json: HideoutJson; warnings: string[] }
// - валидация: name есть в каталоге (иначе warning + drop — хеш взять неоткуда);
// - дубли имени → ошибка (формат их не умеет, см. §1);
// - x/y/r/fv → приведение типов, r mod 65536;
// - лимит 750 → warning при превышении;
// - сериализация: JSON + BOM, вывод=UTF-8 BOM как у игры.

writeHideoutFile(json): string   // текст файла для Blob/скачивания
rebaseHideout(json, newBaseHash, opts?: { keepCoords?: boolean }): { json, warnings }
// конвертер баз: swap name/hash; keepCoords=true warns о разных системах координат
// (§1) и предлагает bbox-нормализацию: сдвиг в observed-диапазон новой базы.

substituteFree(json): { json, replacements: string[] }
// «детокс» MTX: store-mtx/exclusive имена → фряженные аналоги по карте замен
// (map: 'Fire Waypoint'→'Waypoint', 'Kraken Guild Stash Skin'→'Guild Stash', ...)
// Map вручную в decor.json как "free_substitute". Каталог мал — заполняется руками.
```

⚠️ Правило честности: генератор ставит **только** каталогизированные декоры.
Палитра вне каталога — кнопка «нет в каталоге → пришли свой .hideout» (кроудсорс
каталога как у POH, но режим у нас офлайн).

### 4.2 web: режим «Планировщик» во вкладке Хайдоуты

- Переключатель режимов: [Анализ №199] / [Планировщик].
- Канвас: сетка, per-base scale из `observed` bounds (учить: фон = скриншот базы ❓
  пока нет карт — просто границы + центр), объекты как маркеры (имя+иконка категории).
- Палитра декора: фильтр по категории/базе (seen_in), клик → клик по канвасу = place.
- Операции: drag, r колесом (шаг 1024 ≈ 5.6°), fv циклом 0..N, delete, duplicate
  ( только если не конфликт имени — а он будет, дубль запрещён ⇒ duplicate = disabled
  до澄清ения семантики дублей ❓).
- Экспорт: «Скачать .hideout» (Blob, BOM), share-код (сущ. encodeHideoutCode),
- Границы: маркеры «observed bbox» новой базы; жёлтая зона = нерабочая гипотетика.

### 4.3 MCP: `poe2_hideout_parse` / `poe2_hideout_build`

Parse — дёшево, поверх готового core (в Next Move с №199). Build — тоже (MCP не
пишет файлы? — нет, возвращает текст; хост сохраняет).

## 5. Риски / неизвестное

- ❓ Дубли: позволяет ли игра 2+ одинаковых декора и как экспортирует? Тест
  владельца: поставить два, экспортировать. Если `(Unique)` — это маркер копии —
  корректируем buildHideout.
- ❓ Импортирует ли игра сгенерированный файл (валидация hash/server-side)? Тест
  владельца: импорт минимального файла (Stash+Waypoint на Titan Apex).
- ❓ fv>128 у нативных — семантика бита 7 не подтверждена игрой.
- ⚠️ decor.json теперь с `bases.observed` и `bases.music` — back-compat: старые
  читатели не ломаются (только новые поля). Тесты прошли 174/174.

## 6. Этапы реализации

1. core buildHideout/writeHideoutFile + rebase + substitute + тесты (круговая:
   build → parse → summarize). Гейт: vitest + tsc.
2. web-режим «Планировщик» (канвас, палитра, экспорт Blob). Гейт: vite build +
   e2e по паттерну `scripts/e2e-hideout.mjs` (переиспользовать CDP-стенд №199).
3. MCP-тулы parse/build.
4. Живой тест в игре: импорт сгенерированного + эксперимент дублей.
